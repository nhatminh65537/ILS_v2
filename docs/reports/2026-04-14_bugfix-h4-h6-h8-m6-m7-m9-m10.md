## Key Implementations

### Quiz Progress Route Wiring + Contract Stabilization

1. Added quiz progress route mapping in `backend/api/urls.py` to expose existing `QuizViewSet.progress()` implementation.
2. Standardized progress serialization output fields (`user_id`, `quiz_id`, aggregate score/attempt/timestamp fields).
3. Added test coverage for two deterministic cases: existing progress record and no-record fallback payload.
4. Ensured response shape remains stable for frontend consumers and integration scripts.

### Admin User Uniqueness Validation

1. Extended `AdminUserManagementSerializer` with `validate_username` and `validate_email`.
2. Performed case-insensitive uniqueness checks (`iexact`) while excluding the current instance for update paths.
3. Returned DRF field-level validation errors compatible with frontend display logic.
4. Aligned behavior with Slice 8 admin-user API expectations.

### Public Profile Surface + Not-Found UX

1. Removed public profile page from authenticated app route group.
2. Reintroduced page under public route group so `/{locale}/profile/{username}` does not pass through user auth gate.
3. Passed locale explicitly into public profile view for route-safe fallback actions.
4. Replaced plain not-found text with a blocking dialog and explicit “back to home” CTA.

### Account Username-Change Safety Flow

1. Added payload-prebuild path in account form to detect username mutation before submit.
2. Introduced confirmation dialog explaining forced sign-out behavior.
3. On confirm, applied update, attempted server-side session revoke (`logoutAll`), cleared local auth state, redirected to locale login page, and refreshed router state.
4. Preserved non-username update path for regular account updates and state synchronization.

### Error Payload Preservation + Mock Alignment

1. Changed axios error normalization to keep object-shaped validation payloads instead of collapsing to generic `detail`.
2. Updated account form error extraction to prioritize field-level messages (`username`, `email`).
3. Added MSW uniqueness checks for username/email patch and 404 behavior for unknown public usernames.
4. Updated i18n strings for new confirmation and not-found UX states.
