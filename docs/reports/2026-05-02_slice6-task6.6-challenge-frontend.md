## Key Implementations

### Backend — Per-Challenge Progress Endpoint

1. `UserChallengeProgressDetailSerializer` takes `(challenge, user)` in constructor; queries `UserChallengeProgress` + counts `UserChallengeSubmit` directly — no ORM relation traversal overhead
2. Returns `{ is_solved: bool, attempt_count: int, completed_at: datetime|null }` — matching `ChallengeProgressDetailResponse` on the frontend
3. Registered as `challenge_progress` action on `LearnChallengeViewSet` at `GET /api/challenge/challenges/{slug}/progress/`

### Flag Submit Form — Client-Side Throttle

1. On any submission result (`submitResult !== null`), sets `throttled = true` via `useEffect`
2. `setTimeout(2000)` clears `throttled` — button re-enables after 2s regardless of correct/incorrect
3. On correct result, clears the input field and disables it permanently (challenge solved)
4. Feedback badge (CheckCircle2/XCircle) shown immediately after submit, cleared on next attempt

### Instance Panel — Conditional Rendering

1. Only rendered in `ChallengeDetailClient` when `challenge.instance_required === true`
2. Derives display state from `instanceStatus`: running → show connection info + Stop button; no instance → Start button; stopped → Restart button
3. `instance_info` rendered generically as key-value pairs — no hard-coded mock format (Wave 2 compatible)

### Service Path Migration

1. All functions changed from `id: number` to `slug: string` parameter
2. All paths updated from `/api/challenges/{id}/...` to `/api/challenge/challenges/{slug}/...`
3. Old `createChallengeInstance` and `getChallengeTree` removed; new `startInstance`, `stopInstance`, `getInstanceStatus`, `getGlobalProgress` added
4. MSW handlers rewritten in parallel — URL patterns use `*/api/challenge/...` wildcard prefix

## Notes / Caveats

- `ChallengeInstancePanel` uses `instance_info` as generic key-value display — compatible with Wave 2 real deployment data
- The catalog client derives category filter options from `category`/`category_name` fields in the list response. If the backend doesn't return `category_name` in the list serializer for all challenges, category badges will fall back to `Category {id}` labels
- Client-side throttle (2s) on flag submit is intentional and sufficient for MVP; server-side rate limiting is deferred
- Task 6.7 (admin challenge editor) and 6.8 (GitLab sync) remain unimplemented
